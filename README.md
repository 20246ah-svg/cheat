# cheat

Учебный x86-плагин для **Counter-Strike: Source v34 (ClientMod)**, демонстрирующий устройство интерфейсов Source Engine и преобразование мировых 3D-координат в экранные 2D-координаты. DLL создаёт информационный ESP-оверлей: рамки игроков и линии до них окрашиваются по принадлежности к команде.

> Проект предназначен для изучения реверс-инжиниринга, C++ и 3D-математики в локальной игре либо на тестовом сервере, где у вас есть разрешение. Не используйте его для обхода античита или получения преимущества на публичных серверах.

## Возможности

- поиск экспорта `CreateInterface` во всех загруженных модулях ClientMod и получение `VEngineClient013`, `VClient017`, `VClientEntityList003`, `VGUI_Surface030` и `VGUI_Panel009`;
- чтение локального игрока, списка сущностей и полей игровых объектов;
- перспективная проекция `WorldToScreen` через матрицу вида-проекции;
- VMT-хук `IPanel::PaintTraverse` (индекс `41`);
- получение разрешения через `ISurface::GetScreenSize`;
- отрисовка рамок и направляющих линий средствами `ISurface`;
- зелёный цвет для своей команды и красный для команды противника;
- автоматическое включение оверлея после установки хука; клавиша **Insert** остаётся дополнительным переключателем;
- диагностические MessageBox и тестовый красный квадрат в `PaintTraverse` (включены по умолчанию).

## Требования

- Windows;
- Visual Studio 2019 или новее с компонентом **Desktop development with C++**;
- CMake 3.15+;
- 32-битная версия ClientMod/CSS v34.

Проект собирается как C++17 DLL строго под **Win32/x86**. DLL другой архитектуры нельзя загрузить в 32-битный `hl2.exe`.

## Сборка с CMake

Откройте **Developer Command Prompt for VS** в каталоге проекта и выполните:

```bat
cmake -S . -B build -A Win32
cmake --build build --config Release
```

Результат:

```text
build\Release\cheat.dll
```

Чтобы собрать отладочную конфигурацию:

```bat
cmake --build build --config Debug
```

Диагностика включена по умолчанию. После проверки её можно отключить:

```bat
cmake -S . -B build-clean -A Win32 -DCHEAT_DIAGNOSTICS=OFF
cmake --build build-clean --config Release
```

Можно также открыть созданный файл `build\cheat.sln` в Visual Studio и выбрать платформу **Win32**.

## Запуск в учебном окружении

1. Запустите 32-битный ClientMod (`hl2.exe`) и откройте локальную карту или разрешённый тестовый сервер.
2. Загрузите абсолютный путь к `cheat.dll` в процесс стандартным методом `LoadLibraryA` из выбранного вами x86 DLL-loader/debugger.
3. Первый MessageBox `DLL loaded!` подтверждает выполнение `DllMain`. Нажмите **OK**.
4. Второй MessageBox сообщает, удалось ли получить интерфейсы и установить хук `PaintTraverse`.
5. Оверлей включается автоматически. **Insert** можно использовать, чтобы скрыть или снова показать его.

Инжектор намеренно не входит в репозиторий: DLL совместима с обычным способом загрузки через `LoadLibrary` и может исследоваться под отладчиком в контролируемой среде.

## Диагностика рендера

При `CHEAT_DIAGNOSTICS=ON` хук всегда рисует красный прямоугольник `100×100` в координатах `(400, 300)` — `(500, 400)`. Он не зависит от списка сущностей и `ViewMatrix`.

- нет первого MessageBox — DLL не исполняется или загружена неверная архитектура;
- после первого окна DLL ждёт интерфейсы не более 10 секунд, затем проверяет наличие экспорта `CreateInterface` и выводит найденные версии интерфейсов;
- второе сообщает `PaintTraverse hook installation failed` — не удалось заменить VMT-слот;
- второе сообщает об успешном хуке, но перечисляет gameplay-интерфейс — тестовый квадрат уже должен работать, а ESP ждёт исправления указанного интерфейса;
- хук установлен, но квадрата нет — проверяйте имя панели и индексы методов `IPanel`/`ISurface`;
- квадрат есть, но ESP нет — хук и базовый рендер исправны, проблема находится в сущностях, смещениях или `WorldToScreen`.

Статус инициализации также отправляется в отладчик через `OutputDebugStringA`.

## Как устроен проект

| Файл | Назначение |
| --- | --- |
| `main.cpp` | `DllMain`, отдельный поток инициализации |
| `engine.h/.cpp` | получение интерфейсов и доступ к адресам модулей |
| `entity.h` | представление `CBaseEntity` и чтение полей |
| `vector.h` | `Vector`, `Vector2`, `Vector4`, `Matrix4x4` и математика |
| `esp.h/.cpp` | `WorldToScreen` и отрисовка ESP |
| `hooks.h/.cpp` | установка и снятие VMT-хука `PaintTraverse` |
| `CMakeLists.txt` | конфигурация C++17 DLL для MSVC Win32 |

### Поток данных

1. DLL перечисляет модули текущего `CMLauncher.exe`, находит экспорт `CreateInterface` и определяет владельца каждого интерфейса без зависимости от старых имён `engine.dll`/`client.dll`.
2. `IClientEntityList` перечисляет сущности игроков.
3. Из каждой активной сущности читаются позиция, здоровье и номер команды.
4. `Matrix4x4::TransformPoint` переводит мировую точку в clip space.
5. После деления на `w` координаты NDC переводятся в пиксели текущего экрана.
6. Во время `MatSystemTopPanel::PaintTraverse` `ISurface` рисует рамку и линию.

## Смещения ClientMod v34

| Поле | Значение |
| --- | ---: |
| `dwLocalPlayer` | `client.dll + 0x4C88EC` |
| `dwEntityList` | `client.dll + 0x4C5C1C` |
| `dwViewMatrix` | `engine.dll + 0x4A3D64` |
| `dwEngine` | `engine.dll + 0x3C5C64` |
| `m_iHealth` | `0x90` |
| `m_iTeamNum` | `0x98` |
| `m_vecOrigin` | `0x134` |
| `m_bDormant` | `0xE9` |

Смещения и индексы виртуальных методов зависят от конкретной сборки. Если ClientMod обновился, перед запуском проверьте их в отладчике; неверное значение может привести к аварийному завершению `hl2.exe`.

## Математика WorldToScreen

Для мировой точки `p = (x, y, z, 1)` вычисляется:

```text
clip = ViewProjectionMatrix * p
ndc.x = clip.x / clip.w
ndc.y = clip.y / clip.w
screen.x = width  / 2 * (1 + ndc.x)
screen.y = height / 2 * (1 - ndc.y)
```

Точки с `clip.w <= 0.001` находятся позади камеры и не отрисовываются.
